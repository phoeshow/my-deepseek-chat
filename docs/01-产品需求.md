# 01 · 产品需求

## 1. 背景与目标

本地自用的 AI 聊天助手。不追求成为通用产品，追求三件事：

1. **用得顺**：流式输出、代码高亮、多会话，键盘全流程不碰鼠标。
2. **看得清**：思考模式下能展开看模型怎么想的；随时知道花了多少上下文、缓存命中多少。
3. **存得牢**：所有数据在本地 SQLite，可导出，中断不丢。

### 非目标（v1 明确不做）

不做云同步、账号体系、团队协作、移动端、插件市场、自动更新、i18n。

## 2. 目标用户与场景

单一用户（开发者本人），单人单机。典型场景：

| 场景 | 关键诉求 |
|---|---|
| 写代码时问 API 用法 | 代码块高亮 + 一键复制；深度思考看推理过程 |
| 写周报/文档 | 长文可读性（行高、宽度）；追问上下文不丢 |
| 学习新领域 | 多会话隔离不同主题；会话标题一眼可辨 |
| 排查疑难问题 | 思考模式观察推理链；可重新生成对比不同回答 |

## 3. 功能清单（v1）

图例：`P0` 必须交付 · `P1` 应交付（有则更好）· `—` 不在 v1

### 3.1 会话管理

| # | 功能 | 优先级 | 交互说明 | 验收标准 |
|---|---|---|---|---|
| S1 | 新建会话 | P0 | `⌘/Ctrl+N`；新会话自动聚焦输入框 | 新会话立即可用，左栏顶部插入 |
| S2 | 会话重命名 | P0 | 双击标题就地编辑；`Enter` 确认 / `Esc` 取消 | 空标题不被接受，回退原名 |
| S3 | 删除会话 | P0 | 悬停显示 `⋯` 菜单 → 删除 → 二次确认 | 消息随会话级联删除，不留孤儿行 |
| S4 | 归档会话 | P1 | 同上菜单 → 归档；左栏底部「已归档」入口 | 归档会话不出现在主列表与搜索结果，可从「已归档」恢复 |
| S5 | 列表排序 | P0 | 按 `updated_at` 倒序 | 每次生成完成后会话置顶 |
| S6 | 自动标题 | P1 | 首轮回答结束后调模型生成 ≤20 字标题 | 失败则保留首条用户消息前 30 字，不阻塞主流程 |
| S7 | 生成中标识 | P0 | 左栏会话项右侧跳动小点 | 切换到别的会话时仍能看出哪个在生成 |
| S8 | 快速切换 | P1 | `⌘/Ctrl+K` 聚焦左栏搜索框（v1.1 起该框同时支持全文搜索） | 输入即筛选，`↑↓` 选择，`Enter` 跳转 |
| S10 | 用量统计 | P1 | 左栏底部「用量」→ 中栏仪表盘；范围：今日 / 近 7 天 / 全部 | 卡片（请求数/tokens/缓存命中）、近 7 天柱状、按模型聚合、开销最高的 5 个会话；**不显示费用** |
| S9 | 全文搜索 | P1 | 左栏顶部常驻搜索框；`⌘K` 聚焦 | 标题与消息（含思维链）均可命中；点击结果跳转并高亮目标消息；<3 字符走 LIKE 兜底 |

### 3.2 对话

| # | 功能 | 优先级 | 交互说明 | 验收标准 |
|---|---|---|---|---|
| C1 | 发送消息 | P0 | `Enter` 发送 / `Shift+Enter` 换行 | 发送后输入框立即清空并可继续输入 |
| C2 | 流式输出 | P0 | 逐字上屏；生成中末尾 2px 光标呼吸 | 首 token 到达即渲染；滚动跟随到底部 |
| C3 | 停止生成 | P0 | 生成中发送按钮变 `⏹`；`⌘/Ctrl+.` 或 `Esc` | 已生成内容保留，标记为「已停止」，不报错 |
| C4 | 重新生成 | P0 | 最后一条助手消息悬停 → 重试图标；`⌘/Ctrl+R` | 旧回答保留为兄弟节点，不删除；主线切到新版本 |
| C9 | 版本切换 | P1 | 回答下方常显 `‹ 1/3 ›`，点击切换兄弟版本 | 切换后主线游标落到目标版本分支的末端；越界箭头置灰；不删除任何消息 |
| C10 | 编辑消息并分叉 | P1 | 用户消息悬停 → 编辑；输入框空时按 `↑` 直接编辑最后一条用户消息；`Enter` 保存并发送 / `Esc` 取消 / `Shift+Enter` 换行 | 新内容成为同 parent 下的兄弟版本并生成新回答；原消息与旧分支不删除，可通过该消息的 `‹ 1/2 ›` 切回；生成中不可编辑 |
| C5 | 复制消息 | P0 | 悬停 → 复制整条 | 拷贝为 Markdown 原文（非渲染后 HTML） |
| C6 | 复制代码块 | P0 | 代码块右上角复制按钮 | 复制后 1.5s 显示 ✓；不复制语言标识行 |
| C7 | 失败重发 | P0 | 发送失败的用户消息下方显示「重试」 | 重试复用原消息 id，不产生重复节点 |
| C8 | 多会话并行生成 | P1 | 切换会话时后台请求继续 | 回到该会话时内容仍在增长 |

### 3.3 渲染

| # | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| R1 | Markdown | P0 | 支持标题、列表（嵌套）、表格、引用、分割线、链接（外部浏览器打开） |
| R2 | 代码块高亮 | P0 | Shiki 主题，明暗跟随；超长代码块可横向滚动 |
| R3 | 流式稳定性 | P0 | 生成过程中不出现布局跳动累计；未闭合的代码块有正确降级渲染 |
| R4 | 数学公式 | P1 | 行内 `$...$` 与块级 `$$...$$` |
| R5 | 链接安全 | P0 | 只允许 `https?`；点击前不执行任意协议；外部打开走确认 |

### 3.4 思考模式

| # | 功能 | 优先级 | 交互说明 | 验收标准 |
|---|---|---|---|---|
| T1 | 思维链展示 | P0 | 默认折叠为 `▸ 已思考 2.1s`；点击展开 | 与正文视觉上明确分区（左竖线 + 灰字） |
| T2 | 三级开关 | P0 | 生效优先级：本条临时（输入区控件行）> 会话（标题栏胶囊）> 全局（设置页）。控件形态为 switch，**全局默认开启** | 任何位置都能看出"当前生效值"及其来源；默认开启后新会话直接带思维链 |
| T3 | 思考强度 | P1 | `reasoning_effort`：low / high / max | 与思考开关联动：关闭时该项置灰 |
| T4 | 生成中提示 | P0 | 折叠头显示 `✳ 正在思考…` + 微光扫过 | 思考内容实时流入（即使折叠，展开即可见已生成部分） |
| T5 | 耗时统计 | P1 | 首帧 reasoning 到末帧 reasoning 的差值 | 无 reasoning 时不显示该行 |

> **关于"默认开启"的代价**：思考模式会产生 reasoning tokens，响应更慢、成本更高。
> 默认开启是产品决策（本应用以"看得见推理过程"为核心卖点），用户可在设置页或输入区逐层关闭。
> 老配置通过 `config.version` 1→2 的一次性迁移获得新默认值，之后用户自己的选择不会被覆盖。

## 4. 非功能需求

| 维度 | 指标 | 验证方式 |
|---|---|---|
| 冷启动 | 首屏可交互 < 1.2s | 手动秒表 + 性能面板 |
| 长列表 | 500 条消息滚动不掉帧 | 虚拟化；逐 token 合并渲染 |
| 内存 | 空闲 < 250MB | 任务管理器观察 |
| 中断安全 | 强制 kill 后最多丢 200ms 输出 | 生成中 `kill -9`，重启检查内容 |
| 重启恢复 | 上次模型/参数/分栏宽度/窗口位置全部还原 | 手动回归 |
| 离线可用 | 断网时能浏览全部历史，仅发送时提示无网络 | 拔网线测试 |
| 单实例 | 重复启动聚焦已有窗口 | 连点两次图标 |
| 数据可携带 | `userData` 目录整体拷贝到另一台机器即可用 | 跨机迁移测试 |
| 无障碍 | 正文对比度 ≥ 4.5:1；键盘可达全部主流程 | 对比度检查器 + 纯键盘走查 |

## 5. 边界情况清单（实现时逐条对照）

- 无 Key 首次启动 → 引导页，而不是报错
- Key 失效（401）→ 输入框禁用 + 顶部横幅直达设置
- 余额不足（402）→ 明确文案，不重试
- 流中断 → 保留已收内容，标记「已停止」，可重试
- 请求 30s 无首 token → 自动中止，可重试
- 生成长度触顶（`finish_reason=length`）→ 消息尾部提示「输出被截断，可继续追问」
- 会话内模型已下线 → 发送前校验，提示切换
- 数据库被外部删除 → 启动自建空库，不崩溃
- 生成的标题含换行/超长 → 截断到 20 字并去换行
- 同一会话快速连发两次 → 第二次排队或置灰，不允许并发同会话请求
