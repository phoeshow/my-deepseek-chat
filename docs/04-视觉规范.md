# 04 · 视觉规范

## 1. 设计基调

**极简三栏 · 灰阶为主 · 单一强调色 · 高信息密度**

- 界面本身要"退后"：中性灰阶承载结构，只有一个靛蓝强调色用于可分级的交互点
- 不用大圆角、不用渐变、不用毛玻璃、不用重阴影——层级靠**边框与背景明度差**建立
- 信息密度优先于留白（这是工具，不是落地页），但**消息正文的阅读舒适度优先于一切**

### 2.1 自定义标题栏

应用**不使用系统菜单栏与原生标题栏**，窗口控制由渲染层自绘：

- Linux / Windows：`titleBarStyle: 'hidden'`——实测同样能去掉原生标题栏，且保留系统边框，因此**边缘拖拽缩放是原生的**（`frame: false` 在 Wayland 下会失去缩放能力，需自行实现拖拽热区）
- macOS：`frame: false`——`titleBarStyle: 'hidden'` 会保留红色交通灯，与自绘按钮重复
- 所有平台：`Menu.setApplicationMenu(null)`（macOS 保留最小应用菜单，否则 Cmd+C/V 失效）

```
┌─────────────────────────────────────────────────────────────────────┐
│ ✳ DeepSeek                                          —      □      ✕  │  36px
└─────────────────────────────────────────────────────────────────────┘
   ↑ 拖拽区（-webkit-app-region: drag）           ↑ 按钮 40×36（no-drag）
```

| 元素 | 规格 |
|---|---|
| 高度 | 36px，`--bg` 底色，下边 1px `--border` |
| 拖拽区 | 整条标题栏，`-webkit-app-region: drag`；内部文字 `user-select: none` |
| 品牌区 | 左侧 12px 内边距，`faAsterisk`（10px）+ 「DeepSeek」，13/500，`--text-secondary` |
| 窗口按钮 | 每个 40×36，图标 10px（Font Awesome，见 §8），`-webkit-app-region: no-drag` |
| 按钮 hover | 最小化/最大化：`--surface-hover` 底；**关闭：`#E81123` 底 + 白图标** |
| 最大化图标 | 未最大化 `faWindowMaximize`，最大化后换 `faWindowRestore`，`aria-label` 同步变为「还原」 |
| 双击 | 整条拖拽区双击 → 切换最大化 |
| 平台差异 | macOS 把三个按钮放在**左侧**（间距 72px 让开惯用位置）；Linux/Windows 在右侧 |
| 全屏 | 进入全屏时隐藏标题栏（M4 实现），当前固定显示 |

**为什么自绘而不是 `titleBarOverlay`**：原生 overlay 按钮的尺寸与配色由桌面环境决定，无法与「灰阶 + 单一强调色」的视觉语言对齐；而且我们要在标题栏左侧放品牌与折叠入口。

**必须同时处理的三件事**（少一件就会出现“窗口拖不动/拖不了大小”）：

1. 拖拽区用 CSS 类 `.app-drag` / `.app-no-drag` 统一定义，避免组件里手写 `-webkit-app-region`
2. **空白区才是拖拽区**：品牌区与按钮都是 `no-drag`，否则点击会被当成拖拽起始动作吞掉；双击品牌区切换最大化（拖拽区会吞掉双击事件，所以监听放在 no-drag 区域）
3. 缩放能力依赖平台：Linux/Windows 靠 `titleBarStyle:'hidden'` 保留的系统边框；macOS 靠 `frame:false` 自带的可缩放

**折叠行为**：

- 左栏：折叠后中栏顶栏左侧出现 `faBars`；折叠状态与宽度持久化到 `config.json`
- 右栏：折叠后模型胶囊**右侧**出现 `faSliders`；**展开状态不持久化——每次启动都是收起**。理由：参数面板是可选内容，不属于每次都要看的主信息，默认占 280px 会挤掉对话区。宽度仍持久化，用户调过的宽度下次展开时保留。

**入口唯一原则**：设置入口只存在于**左栏底部**一处。中栏顶栏、标题栏、菜单均不重复投放——同一个功能在同一屏内出现两次会迫使使用者每次选择“该点哪个”。同类适用：新建会话只在左栏顶部，导出只在设置页/会话菜单。

**"回到底部"按钮**：距底部 > 300px 时浮现在输入区上方居中，28px 圆形，`surface` 底 + 边框。

## 4. 组件规范与状态

### 4.1 用户消息

- 右对齐，`--bubble-user` 底色，`--radius-md`，padding 10/14，`max-width: 70%`
- 字号 14/1.7，允许 Markdown（代码块带底但无工具条）
- 悬停显示「复制」；发送失败时气泡下方一行 `--danger` 文字 + 「重试」链接

### 4.2 助手消息

- **全宽无气泡**（阅读优先），左对齐
- 头部一行：`faAsterisk` 标记（9px，`--text-tertiary`）+ 模型短名（`--text-micro`，悬停才显）
- 正文 14/1.7，`max-width: 760px` 居中
- 悬停显示操作条：复制 / 重新生成（仅最后一条）
- **版本切换器 `‹ 1/3 ›` 常显**在正文下方（不是 hover 才出现）：它传达"这里有多版回答"这件事，
  藏起来等于让用户不知道旧版本还在。仅当同 parent 下存在多个 assistant 版本时渲染。
  到达首/末版时对应箭头置灰；生成中整体禁用
- 生成中：末尾 2px 宽 `--accent` 竖条光标，1s 呼吸（opacity 1↔0.2）
- 停止后：消息末尾右对齐 `已停止` 角标（11px，`--text-tertiary`）

### 4.4 代码块

|---|---|
| 分组标题 | 13 / 1.5 / 600，`--text-secondary`，下方 8px 间距 |

**「温度」的说明内容**（唯一使用说明图标的参数）

- 取值域与默认值：0 – 2，默认 1.0
- 直觉解释：越低越确定、越高越发散；官方建议只调 `temperature` 或 `top_p` 其中之一
- DeepSeek 官方按场景推荐值（来源 `api-docs.deepseek.com/zh-cn/quick_start/parameter_settings/`）：

  | 场景 | 温度 |
  |---|---|
  | 代码生成 / 数学解题 | 0.0 |
  | 数据抽取 / 分析 | 1.0 |
  | 通用对话 | 1.3 |
  | 翻译 | 1.3 |
  | 创意类写作 / 诗歌 | 1.5 |

- **必须写进浮层的告警**：思考模式开启时 `temperature` 不生效（官方行为：不报错、但被忽略）。由于本应用默认开启深度思考，这是用户最可能误解的地方。
- 推荐值只做**只读展示**，不提供"一键应用"按钮：温度是会话级持续生效的设定，按钮会让人误以为"应用一次即可回到原值"，且会让浮层从"解释"变成"操作"，与信息图标的语义不符。

**发送键（Enter）**

| 状态 | 视觉 |
|---|---|
| 常态 | `--accent` 底 + 白色 `Enter`（等宽、600 字重、`leading-none`）；**4px 扩散光晕**：`0 0 0 4px accent/16%` |
| hover | 底色转 `--accent-hover`，光晕加深到 28% |
| 按下 | `scale(0.9)` + 光晕收紧到 2px / 36% |
| 禁用 | 底色转 `--line`、文字转 `--text-tertiary`、**无光晕**（不用整体透明度，否则白字看不见） |
| 生成中 | 替换为「停止」描边按钮，宽度与 Enter 相当，避免布局跳动 |

文字必须用 `inline-flex + items-center + justify-center + leading-none` 居中：`<button>` 默认行盒受 `line-height` 影响，垂直方向会偏 1–2px。

### 4.9 空态

| 场景 | 内容 |
|---|---|
| 无 API Key | `--text-display` 标题「先配置 DeepSeek API Key」+ 副文案 + 主按钮「打开设置」 |
| 新会话 | 「今天想聊点什么？」+ 3 个示例提示词卡片（12px 灰边，hover 提亮，点击填入输入框） |

### 4.10 说明浮层（InfoTip）

给单个参数/概念配说明时复用这个控件，不要每处手写 tooltip。

```
参数
温度 ⓘ  ← 图标本体（11px，--text-tertiary，hover 转 --text-primary）
      └→ 浮层：260px 宽，距图标 8px，白色/暗色 surface 底 + 1px 边框 + shadow-md
```

| 项 | 规格 |
|---|---|
| 触发 | 鼠标移入、键盘聚焦；移出、失焦、`Esc`、窗口 resize 时关闭 |
| 定位 | 优先图标**右侧**；右侧空间不足放**左侧**；两侧都不够才落到下方并夹进窗口（上下左右各留 12px） |
| 实现 | `createPortal` 挂到 `body` + `position: fixed` |
| 层级 | `z-50` |
| 字色 | 标题 `--text-primary`、正文 `--text-secondary`、说明性小字 `--text-tertiary`、告警 `--warn` |
| 布局 | 场景/取值成对出现时用两列 grid，数值列用等宽字体右对齐 |
| 无障碍 | 图标按钮有 `aria-label`；浮层 `role="tooltip"`；纯装饰不出现在 tab 序列之外 |

**为什么必须 portal + fixed**：参数面板内部是 `overflow-y: auto` 的滚动容器，绝对定位的浮层会被裁掉（表现为浮层只显示一半或被截断）。挂到 body 再按图标 `getBoundingClientRect()` 定位，才能跨越任意祖先的裁剪。

**为什么优先放侧边而不是下方**：放下方会盖住正在解释的控件本身（温度浮层第一版就盖住了滑块和数值），用户读说明时看不到自己调的是哪一个参数。

**只读原则**：说明浮层内不放"一键应用"之类的操作按钮——它承担的是解释职责，操作应留在被解释的控件上，否则同一个能力出现两个入口（见 §2 的入口唯一原则）。

### 4.11 左栏搜索（v1.1）

```
┌─────────────────────────────┐
│ 🔍 搜索会话与消息      ⌘K │  ← 36px，常驻左栏顶部
├─────────────────────────────┤
│ «              ＋ 新对话     │
├─────────────────────────────┤
│ 🔍 你好，先聊两句       会话 │  ← 标题命中（kind=session）
│ 你好，先聊两句              │
│ 你好，世界。                │  ← 消息命中：会话名 + 片段
│ 你好，先聊两句              │
│ 你好，先聊两句              │
└─────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 位置 | 左栏顶部，`＋ 新对话` 之上；常驻，不随折叠状态隐藏 |
| 间距 | 与标题栏之间 **12px**（`pt-3`），左右各 12px，与下方「＋ 新对话」行之间 8px。沿用侧栏既有的 12px 内边距节奏，不要贴住标题栏 |
| 输入框 | 高 32px（含内边距），`faMagnifyingGlass` 左侧，右侧为空时显示 `⌘K` 键帽、有内容时显示清除按钮 |
| 防抖 | 180ms；请求带序号，过期响应直接丢弃 |
| 结果区 | **就地替换左栏会话列表**（骨架不动：搜索框与「新对话」行保持原位） |
| 标题命中 | 行尾标注「会话」，点击直接打开该会话 |
| 消息命中 | 第一行会话名（micro 灰）、第二行片段（最多两行截断）；命中处 `<mark>` 底色 `--accent-subtle`、文字 `--accent` |
| 跳转 | 点击后清空搜索、打开会话、把目标消息滚到视野中央，并短暂高亮（`bg-accent-subtle/35`，2.4s 后自动褪去） |
| 空态 | 「没有匹配的会话或消息」 |
| 键位 | `⌘K` 聚焦并全选；`Esc` 清空并失焦；`Enter` 打开第一条结果 |

**为什么结果不另开浮层**：搜索框在左栏，结果却弹到屏幕中央，视线要来回跑；就地替换列表让"输入—看结果—跳转"在同一条垂直动线上完成。也因此 `⌘K` 不再需要单独的快速切换浮层，原来的输入即搜索。

**命中为什么带"会话"标记**：搜索同时命中会话名与消息内容，两类结果的点击语义不同（一个开会话、一个定位到消息），不区分会让人以为点击没反应。

## 5. 动效

| 场景 | 时长 / 曲线 |
|---|---|
| hover / 选中 | 120ms `ease-out` |
| 面板折叠、分栏拖拽结束吸附 | 180ms `ease-out` |
| 消息入场 | 150ms `opacity 0→1` + `translateY(4px)→0` |
| 思维链展开 | 180ms 高度过渡（`grid-template-rows: 0fr → 1fr`） |
| 流式光标 | 1s `ease-in-out` 无限呼吸 |
| 思考微光 | 1.8s 线性往复 |
| 按键按压 | 120ms `ease-out`，`scale(0.9)` + 光晕收紧 |

**禁止**：消息列表整体重排动画、逐 token 缩放、任何超过 250ms 的动画。

全部动效在 `@media (prefers-reduced-motion: reduce)` 下退化为无动画瞬时切换。

## 7. 无障碍

- 正文对比度 ≥ 4.5:1，大字号/图形 ≥ 3:1（明暗两套令牌都需验证）
- 焦点环统一 `2px --accent` + `2px offset`，**禁止** `outline: none`
- 流式区域 `aria-live="polite"`，但**只在生成结束时播报一次**完整文本（逐 token 播报会让读屏无法使用）
- 生成中按钮有 `aria-busy="true"`
- 所有图标按钮必须有 `aria-label`；纯装饰符号 `aria-hidden="true"`
- 动效尊重 `prefers-reduced-motion`

## 8. 图标

**统一使用 Font Awesome（Free Solid）**，禁止手绘 SVG path，也禁止拿 `▸ ✓ × ⋯ ✦` 这类字符充当图标。

| 规则 | 说明 |
|---|---|
| 唯一来源 | 所有图标在 `src/renderer/src/components/icons.ts` 的 `Icon` 映射里登记，组件只从 `Icon.xxx` 取用 |
| 尺寸 | 通过字号控制（FA 的 svg 是 1em 见方）：标题栏 10px、列表内 11–12px、消息内 8–10px |
| 颜色 | 继承 `currentColor`，由父级文字色决定，不单独设色 |
| 静态引入 | `config.autoAddCss = false` + 一次性引入 `@fortawesome/fontawesome-svg-core/styles.css`，避免运行时注入样式导致首帧抖动 |
| 无障碍 | 纯装饰图标加 `aria-hidden`；图标按钮必须有 `aria-label` |

**为什么不用自绘 SVG**：图标要跨明暗主题、跨 DPI 一致，手绘 path 的描边宽度和光学重心很难统一；字符图标则会随字体回退在不同机器上漂移（`▸` 在部分中文字体里是方块）。

当前图标集合（21 个）：

| 用途 | 图标 |
|---|---|
| 窗口控制 | `faWindowMinimize` / `faWindowMaximize` / `faWindowRestore` / `faXmark` |
| 品牌与助手标记 | `faAsterisk` |
| 导航布局 | `faAnglesLeft` / `faAnglesRight` / `faBars` / `faSliders` |
| 会话与设置 | `faPlus` / `faEllipsis` / `faGear` |
| 消息操作 | `faCopy` / `faCheck` / `faRotateRight` |
| 展开指示 | `faChevronRight` / `faChevronDown` |
| 说明提示 | `faCircleInfo`（见 §4.10） |

**例外**：输入区的「Enter」与生成中的「停止」是文字按钮，不是图标按钮——它们需要明确表达键位，图标无法传达。

**体积代价**：Font Awesome 核心 + 按需图标使渲染层 bundle 从 574KB 增至 732KB（未使用图标已被 tree-shaking 剔除，已验证）。本地应用从磁盘加载，代价可接受。

## 9. 文案规范

- 中文全角标点，英文/数字与中文之间留一个空格
- 按钮用动词短语：`新建对话`、`重新生成`、`导出 Markdown`
- 错误文案三段式：**发生了什么 + 为什么 + 怎么办**。例：「请求被限流（DeepSeek 每分钟请求数超限）。已自动重试 3 次仍未成功，请稍后再试。」
- 禁止在界面文案里出现 `Error`、`Exception`、堆栈信息（进日志）
