## 2. 实现顺序建议

先纵向打通再横向铺开：M0 → M1 让"一句话能流出来"最先可见，**避免先把 UI 做完美却调不通 API**。M3 的视觉任务可以并行拆成"渲染（3.1/3.2）"和"外壳（3.4/3.6/3.7）"两条线。

## 4. 风险清单

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | **DeepSeek 模型命名持续迭代**（`deepseek-chat` / `deepseek-reasoner` 已在弃用过渡期，主线为 `deepseek-v4-pro` / `deepseek-v4-flash`） | 写死模型名会导致某天全线报错 | 运行时 `GET /models` + 本地缓存 + 允许手填模型 ID；代码里不出现任何模型名字面量 |
| R2 | **better-sqlite3 原生模块跨平台打包** | 其他平台装不上 | 每个目标平台单独 rebuild；`asarUnpack` 放出 `.node`；CI 矩阵构建 |
| R3 | **流式渲染性能** | 逐 token setState 导致掉帧、长对话卡死 | rAF 批量合并 + 只更新增长中的那条消息 + 列表虚拟化 |
| R4 | **`reasoning_content` 回传规则变化**（带 `tools` 时必须回传，否则 400） | 未来加工具调用时踩坑 | 规则集中在 `ContextBuilder` 一处；v1 参数位保留；加回归测试 |
| R5 | **上下文预算估算不准** | 用户误判成本 | 用每次响应 `usage.promptTokens` 回写校准锚点；宁高估不低估 |
| R6 | **Shiki 拖慢首屏** | 冷启动超 1.2s | 语言与主题按需动态 import；只预载 8 种常用语言 |
| R7 | **`usage` 帧字段位置需实测** | 预算条可能与实际不符 | M1 阶段先用真实响应确认字段名与出现时机 |
| R8 | **Electron 安全配置遗漏** | 本地 Key 泄露 | 对照 02 §8 清单逐条勾选；CSP 用注释写明为何是 `connect-src 'none'` |
| R9 | **单机单人假设被打破**（多用户/多窗口共享 `userData`） | 数据竞争 | 单实例锁已覆盖；文件锁由 SQLite 兜底 |
| R10 | **Wayland / 平铺式桌面的窗口几何语义差异**：窗口在 `show()` 之前没有真实几何（会返回合成器未分配的假值）；自动平铺桌面（GNOME 平铺扩展等）会把平铺状态报为 `isMaximized()=true`，并给出平铺后的 normal bounds | 窗口尺寸/位置存错，下次启动尺寸异常 | 采样必须在 `ready-to-show` 之后（已实现，见 `window.ts` 注释）；写入前做 plausibility 校验 + 恢复时夹回屏幕工作区；退出阶段一律不重新采样，只落盘最后一次合法值 |

## 5. 开放问题（实现前需确认，或按默认值推进）

| # | 问题 | 默认决策 |
|---|---|---|
| Q1 | 是否需要"继续生成"（截断后从断点续写）？ | v1 不做，只提示「输出被截断」，让用户追问 |
| Q2 | 自动标题用哪个模型？ | 用当前会话模型，`max_tokens` 限 32，失败即回退首句截断 |
| Q3 | `better-sqlite3` 未来的替代路径？ | 记录备选：`node:sqlite`（需验证 Electron 是否内置），抽象一层 `Db` 接口以便替换 |
| Q4 | 导出全量 JSON 是否需要"再导入"？ | v1 只导出；导入放 v1.1，格式已预留 `format` / `version` 字段 |
| Q5 | 多窗口（同一会话在两窗口开着）？ | v1 单窗口，`active_leaf_id` 变更时以最后写入为准 |
