# 02 · 系统架构

## 1. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 外壳 | Electron（`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`） | 单窗口 + 单实例锁 |
| 构建 | electron-vite | 一份配置产出 main / preload / renderer 三份产物，HMR 就绪 |
| 打包 | electron-builder | Linux AppImage + deb、macOS dmg、Windows nsis |
| UI | React 19 + TypeScript | 并发特性用于渲染层调度 |
| 样式 | Tailwind CSS v4 + CSS 变量 | 主题令牌以变量注入，见 04 |
| 无障碍原语 | Radix Primitives（按需，不引整套设计系统） | Dialog / Dropdown / Tooltip / Slider / Switch |
| 状态 | Zustand | 三五个 store 即可，避免全局 reducer 样板 |
| DB | **better-sqlite3**（主进程，同步 API） | 需 `electron-rebuild`；打包时 ABI 对齐 |
| 校验 | zod | 所有 IPC 入参、API 配置、导出格式 |
| Markdown | react-markdown + remark-gfm + rehype-katex | 组件映射自定义代码块 |
| 高亮 | Shiki（按语言懒加载） | 预编译主题，避免首屏卡顿 |
| 虚拟滚动 | @tanstack/react-virtual | 消息列表 |
| 日志 | electron-log | 滚转文件，脱敏（永不写 Key） |

## 2. 进程模型

```
┌───────────────────── Renderer（沙箱，无 Node） ─────────────────────┐
│  React 组件                                                          │
│  store/  chat · sessions · settings · models                         │
│  useChatStream()：收帧 → 合并 → rAF 批量 setState → 渲染             │
│  可调用：仅 window.api.*（preload 白名单）                            │
│  CSP: connect-src 'none'  ← 渲染层不发任何网络请求                    │
└──────────▲──────────────────────────────────────┬────────────────────┘
           │ ipcRenderer.on('chat:frame')          │ invoke('...')
           │ （单向事件，主→渲染）                   │ （请求-响应）
┌──────────┴──────────────────────────────────────▼────────────────────┐
│                           Main Process                                │
│                                                                       │
│  IpcRouter        zod 校验 + 错误归一（统一 { ok, data } | { ok:false, code }）│
│  ChatService      请求生命周期状态机 · AbortController · 退避重试     │
│    └ DeepSeekClient   fetch + ReadableStream → SSE 解析 → 归一帧     │
│  SessionRepo / MessageRepo / UsageRepo      better-sqlite3（同步）   │
│  SecretService    safeStorage 加解密 + 文件读写                       │
│  SettingsService  config.json 读写 + 默认值合并                       │
│  FlushScheduler   200ms 定时器，把流式增量落库                       │
│  WindowManager    窗口状态、单实例、生命周期                          │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ HTTPS，仅允许 settings.baseUrl 单一 host
                                ▼
                        api.deepseek.com
```

### 关键约束（不满足即为 Bug）

1. **渲染层永不接触明文 Key**。`secret:*` 通道只返回 `{ hasKey: boolean }`，测试连接的请求在主进程里做。
2. **渲染层无出网能力**。CSP `connect-src 'none'`，所有 HTTP 都在主进程。
3. **主进程只请求一个 host**。`baseUrl` 变更需用户显式操作，且在请求前做 host 校验。
4. **同一会话不允许并发请求**。UI 层置灰 + 主进程层再校验一次。

## 3. 模块职责边界

| 模块 | 该做 | 不该做 |
|---|---|---|
| `IpcRouter` | 参数校验、错误码归一、鉴权（Key 是否存在） | 业务逻辑、数据库访问 |
| `ChatService` | 状态机、组装 messages、发起/中止、重试策略、帧广播 | 解析 SSE（交给 client）、写库（交给 repo + flush） |
| `DeepSeekClient` | 构造请求、解析 SSE、`usage` 提取 | 重试、持久化、UI 决策 |
| `MessageRepo` | CRUD、主线回溯 SQL | 拼装 API 请求体 |
| `ContextBuilder` | 由会话树 + 参数拼出 `messages[]`，按需决定是否回传 reasoning | 发请求 |
| `FlushScheduler` | 节流落库、结束时的最终 flush | 计算 token |
| `SecretService` | 加解密、降级策略、权限位 | 发请求 |

### 4.3 帧协议

主进程把 SSE 归一化为 6 种帧，渲染层只需处理这 6 种：

```ts
type Usage = {
  promptTokens: number
  completionTokens: number
  reasoningTokens?: number
  cacheHitTokens?: number
  cacheMissTokens?: number
}

type ChatFrame =
  | { requestId: string; type: 'start';  assistantMessageId: string; startedAt: number }
  | { requestId: string; type: 'think';  delta: string }   // 源: delta.reasoning_content
  | { requestId: string; type: 'text';   delta: string }   // 源: delta.content
  | { requestId: string; type: 'usage';  usage: Usage }    // 需 stream_options.include_usage = true
  | { requestId: string; type: 'end';    reason: 'stop' | 'length' | 'aborted'; usage?: Usage; endedAt: number }
  | { requestId: string; type: 'error';  code: AppErrorCode; message: string; retryable: boolean }
```

**渲染层合并规则**（性能关键）：

- `think` / `text` 只写入可变缓冲区，用 `requestAnimationFrame` 每帧最多 `setState` 一次
- `end` / `error` 必须触发一次强制 flush，防止最后几个字符丢失
- 每帧只对**正在增长的那一条消息**做局部更新，不重排整个列表

## 5. 请求构造（ContextBuilder）

每次发自前，由会话树 + 参数组装请求体：

```
1. 取主线：从 parentId（本次的父消息）沿 parent_id 回溯到根 → 正序
2. 映射为 API messages：
   - system：若会话设了 systemPrompt，置于首条
   - user：{ role:'user', content }
   - assistant：{ role:'assistant', content, reasoning_content? }
3. reasoning_content 回传规则（★ 硬性要求）
   - 请求体携带 tools  → 必须回传每条历史 assistant 的 reasoning_content，否则 400
   - 请求体不含 tools  → 不回传（传了也会被忽略），省 token
   - v1 不实现 tools，因此 ContextBuilder 默认不回传，但参数位保留
4. 合并参数（优先级：本条 overrides > 会话设定 > 全局默认）
5. stream: true, stream_options: { include_usage: true }
```

**上下文预算计算**：发送前用本地估算（字符数 / 2.2 近似 token，或使用最近一次 `usage.promptTokens` 作为校准锚点）算出预计占用，与 `context_window` 比对驱动 UI 预算条。精确值以响应中的 `usage` 为准，回写后下一次估算更准。

## 6. 流式生命周期状态机

```
        ┌──────────┐
        │   idle   │
        └────┬─────┘
   chat:send │
        ┌────▼──────────┐   HTTP 错误 / 超时
        │  requesting   ├──────────────► error（终态，可重试）
        └────┬──────────┘
 首帧(think) │
        ┌────▼──────┐  首帧即 text
        │ thinking  ├────────┐
        └────┬──────┘        │
       首个 text 帧           │
        ┌────▼───────────────▼┐
        │      streaming      │◄── 后续 think/text 交替
        └───┬─────┬───────┬───┘
   finish   │     │ abort │ 流中断
            │     │       │
      ┌─────▼──┐ ┌▼───────┐┌▼────────┐
      │  done  │ │aborted ││ error   │
      └────────┘ └────────┘└─────────┘
```

每次进入终态都要：`flush()` → 更新 `messages.status` / `tokens_json` → 写 `usage_log` → 广播 `end`/`error` 帧 → 更新会话 `updated_at`。

## 7. 错误模型

```ts
type AppErrorCode =
  | 'AUTH_INVALID'        // 401
  | 'INSUFFICIENT_BALANCE'// 402
  | 'BAD_REQUEST'         // 400（含 reasoning 回传缺失）
  | 'VALIDATION'          // 422
  | 'RATE_LIMITED'        // 429
  | 'SERVER_ERROR'        // 5xx
  | 'NETWORK'             // DNS/连接重置
  | 'FIRST_TOKEN_TIMEOUT' // 30s 内无任何帧
  | 'STREAM_INTERRUPTED'  // 中途断开
  | 'NO_API_KEY'
  | 'UNKNOWN'
```

| 错误码 | UI 表现 | 自动重试 |
|---|---|---|
| `AUTH_INVALID` | 顶部横幅「API Key 无效」+ 直达设置按钮 | 否 |
| `INSUFFICIENT_BALANCE` | 横幅「余额不足」 | 否 |
| `BAD_REQUEST` | 消息内「内部错误」+ 展开看详情 | 否 |
| `VALIDATION` | 定位到具体参数并高亮 | 否 |
| `RATE_LIMITED` | 静默倒计时 `1s → 2s → 4s` | **是，最多 3 次** |
| `SERVER_ERROR` | 消息内错误态 + 「重试」 | 否（手动） |
| `NETWORK` | 「网络不可用」 | 是，1 次 |
| `FIRST_TOKEN_TIMEOUT` | 「响应超时」+ 重试 | 否 |
| `STREAM_INTERRUPTED` | 保留已收内容 + 「已停止」角标 | 是，1 次 |
| `NO_API_KEY` | 引导页 | 否 |

重试统一走 `ChatService` 的退避函数，且**保留原 user 消息与 assistant 消息 id**，不产生重复节点。

## 8. 安全清单

| 项 | 措施 |
|---|---|
| 渲染进程隔离 | `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true` |
| 无边框窗口 | 隐藏原生标题栏：Linux/Windows 用 `titleBarStyle: 'hidden'`（保留系统边框 → 边缘缩放原生可用），macOS 用 `frame: false`（避免与自绘按钮重复的交通灯）；菜单栏统一用 `Menu.setApplicationMenu(null)` 去掉（macOS 保留最小应用菜单）；拖拽区与按钮严格用 `.app-drag` / `.app-no-drag` 区分 |
| 菜单 | 非 macOS 平台 `Menu.setApplicationMenu(null)`；macOS 保留最小应用菜单（复制/粘贴等快捷键依赖它）；去掉菜单后 DevTools 快捷键用 `before-input-event` 补回（仅开发期） |
| preload 暴露面 | 只暴露 `window.api` 上列出的方法，不导出 `ipcRenderer` 本体 |
| CSP | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none'` |
| 外链 | `setWindowOpenHandler` 一律 `deny`；`shell.openExternal` 仅放行 `https?:` 且需确认 |
| SSRF | 请求前校验 `baseUrl` 协议与 host；不允许 `file:`、`localhost`、内网段以外的非配置 host |
| 密钥 | `safeStorage` 加密；降级为明文时 `chmod 600` 并在设置页显示警告 |
| 日志脱敏 | electron-log 过滤器替换 `sk-*`、`Authorization` |
| 数据目录 | `app.getPath('userData')`，不写系统其他位置 |

## 10. 构建与打包要点

- **better-sqlite3 原生模块**：`electron-rebuild -f -w better-sqlite3`；CI 里对每个目标平台单独构建。electron-builder 需配合 `asarUnpack` 放出 `.node` 文件。
  - 注意：better-sqlite3 v13 是 **N-API 预编译**，打包产物里没有 `build/Release`，运行时实际加载 `prebuilds/linux-x64.node`。它自带 8 个平台的预编译共 17MB，必须在 `files` 里裁到当前平台（现为 2.2MB）。
- **Linux 产物**：`AppImage` + `deb` 两个目标（`linux.target`）。
  - `deb` 由 electron-builder 内置的 **fpm** 产出（首次构建自动下载 1.17.0 + 自带 Ruby，无需系统安装）；`dpkg` 也不是必需的。
  - `deb` 三个易错字段：`maintainer` 必填、`Homepage` 取自 package.json 的 `homepage`（缺失会直接报错）、Debian 的 Section 字段在配置里叫 **`packageCategory`**（`category` 指 freedesktop 应用分类）。
  - `syncDesktopName: true` + package.json `desktopName`：让 `.desktop` 文件名、`StartupWMClass`、Electron 的 `app_id` 三者一致，否则桌面环境无法把运行中的窗口关联到桌面项。
  - `deb` 的 `Exec` 路径含空格（`/opt/DeepSeek Chat/...`，源自 productName），electron-builder 已加引号；若要绝对避免，可把 productName 改成无空格形式并单独覆盖 `linux.desktop.entry.Name`。
- **Shiki 体积**：按需 `import 'shiki/langs/ts'` 等常用语言，其余走动态 import；主题只打包两套（亮/暗）。
- **首次启动迁移**：`PRAGMA user_version` 与 `migrations/` 索引对齐，启动时顺序执行缺失迁移，包在事务里。
- **单实例**：`app.requestSingleInstanceLock()`，第二实例 `quit` 并让首实例 `focus()`。
